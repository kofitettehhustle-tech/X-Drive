# Managed PostgreSQL provider research (2026-10-13)

Sources accessed 2026-10-13; provider limits can change and should be rechecked before setup.

- Neon official pricing: https://neon.com/pricing
  - Free plan is permanent and no card required; 100 CU-hours/project, up to 2 CU autoscaling, 1 GB/project storage, 20 GB total account storage, 5 GB egress/project, compute scales to zero after 5 minutes; free usage limits may block writes or suspend compute until the next billing period.
- Supabase official pricing: https://supabase.com/pricing
  - Free plan: 500 MB database/project, 5 GB egress, two active projects; projects pause after 1 week of inactivity; no automatic backups listed for Free.
- Aiven official free PostgreSQL: https://aiven.io/free-postgresql-database
  - Free managed plan lists 1 GB storage, 1 GB RAM, 1 CPU, one node, no time limit, backups/network included; service powers off after inactivity; explicitly not recommended for high-traffic production.

Initial suitability note: all three may work for preview/testing, but free-tier inactivity, resource, backup, and availability limitations make them unsuitable to assume as durable production wallet/order infrastructure without checking current terms and planning backups. A generic Node `pg` driver and `DATABASE_URL` can be provider-neutral, but migrating the synchronous SQLite stores to PostgreSQL requires async data-layer changes and new package-lock validation.


## Supabase connection guidance (official docs, accessed 2026-10-13)

- Connect guide: https://supabase.com/docs/guides/database/connecting-to-postgres
  - On the Supabase project dashboard, click Connect and copy the exact connection string; replace the password placeholder with the database password and percent-encode reserved characters.
  - Direct connection is IPv6 (unless the IPv4 add-on exists). The shared session pooler is IPv4 on every plan and uses a different username/host; it is the documented fallback for an IPv4-only persistent backend.
  - Session pooling supports prepared statements; transaction mode does not.
- Pool limits: https://supabase.com/docs/guides/database/connecting-to-postgres/pooling-and-limits
  - App-side `pg.Pool` should be kept small; the backend is a persistent Render service, and an app-side pool is the usual approach. Keep below free database connection limits.
- Supabase Render guide: https://supabase.com/docs/guides/platform/migrating-to-supabase/render
  - Supabase recommends using the project Connect panel, Session pooler, and copied URI for IPv4 networks.
- `pg` connection docs: https://node-postgres.com/features/connecting
  - `pg.Pool` accepts a connection URI and can read libpq-style environment variables.
